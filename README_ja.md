# video-autotag ― 全部開かなくても、ライブラリにタグの下書きを

ローカルライブラリは増え続けるのに、タグ付けのやる気は全然ついてこなかった。何百本ものファイル、その大半が `final_v2.mp4` みたいな名前で、Stash のようなライブラリツールはタグを入れてなんぼ——でもその入力を私は永遠に先延ばしにしていた。

なので手抜き版を作った。フォルダを渡すと、各動画を数フレームだけ代わりに見て、見えたものを書き留めてくれる。完成版のタグではなく、ざっと目を通して直せる下書き。白紙のタグ欄を前に固まるよりはマシ、という発想。

## 仕組み

1. **ffmpeg** が各動画から均等に N 枚の静止画を抜く（ffprobe で長さと解像度を先に取得）。
2. **CLIP**（`openai/clip-vit-base-patch32`、transformers でローカル実行）が全フレームをタグ語彙と照合してスコア付け——学習なし、API キーなしのゼロショット分類。
3. 同じカテゴリ内のラベル同士が競合し（室内 vs 屋外、クローズアップ vs ワイドショット）、フレームごとに投票、ラベルごとに**全フレーム中の最高スコア**を採用。しきい値以上だけが結果に入る。

動画ごとに sidecar ファイルができる。`movie.mp4` → `movie.tags.json`：

```json
{
  "file": "dark_text.mp4",
  "duration_sec": 6.0,
  "resolution": "640x360",
  "frames_sampled": 5,
  "model": "openai/clip-vit-base-patch32",
  "threshold": 0.55,
  "tags": [
    {"label": "indoor", "category": "setting", "score": 0.9634},
    {"label": "dark lighting", "category": "lighting", "score": 0.8482}
  ],
  "all_scores": { "indoor": 0.9634, "outdoor": 0.0001, "...": "..." }
}
```

これは合成テスト動画（黒背景に白文字）に対する実際の出力。`all_scores` には採用分だけでなく全ラベルのスコアが残るので、後からしきい値を変えたくなってもモデルを回し直す必要はない。

## インストール

Python 3.10+ と、PATH の通った ffmpeg / ffprobe が必要。

```bash
# まず CPU 版 torch（デフォルトの CUDA 版よりずっと小さい）
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install -r requirements.txt
```

初回実行時に HuggingFace から CLIP モデルをダウンロードする（約 580 MB、一度だけ）。以降は完全オフライン、CPU のみ、自分のマシンの中だけ。ライブラリの情報が外に出ることはない。

## 使い方

```bash
# フォルダごと（再帰）、sidecar は各動画の隣に
python autotag.py /path/to/library

# 1 ファイルだけ、しきい値厳しめ、フレーム多め
python autotag.py movie.mp4 --frames 8 --threshold 0.7

# 実行全体のサマリー CSV も出す
python autotag.py /path/to/library --out-csv summary.csv
```

| オプション | デフォルト | 意味 |
|---|---|---|
| `--frames` | 5 | 動画ごとに抜くフレーム数 |
| `--threshold` | 0.55 | タグとして採用する最低スコア |
| `--tags` | スクリプト隣の `tags.json` | 使う語彙ファイル |
| `--out-csv` | オフ | サマリー CSV（ファイル名、長さ、解像度、タグ）を書く |

## 語彙は自分のものに

`tags.json` がこのツールの人格のすべて。初期語彙はシーン/構図系の中立なラベル——場所、ショット、照明、カメラ、人数——私がまず片付けたかったのがこれだったから。自由に書き換えてほしい：

```json
{
  "setting": [
    {"label": "indoor", "prompt": "an indoor scene inside a room"},
    "outdoor"
  ]
}
```

- ラベルは**カテゴリ**にまとめ、スコアはカテゴリ内でのみ競合させる。だから排他的なもの同士は同じグループに入れる。
- 文字列だけでも動く（ラベル兼プロンプトになる）。`{"label", "prompt"}` 形式ならプロンプトを自然な一文にできて、CLIP のスコアは単語単体より文のほうが明らかに安定する。
- 自分のライブラリに実際あるものに合わせてカテゴリを足す。初期語彙は出発点であって、何かの分類体系ではない。

## タグの使い道

sidecar JSON はわざと地味にしてある：ファイル名、長さ、解像度、スコア付きタグ。私は Stash などのライブラリツールへ取り込むときの参照表として使っている——候補を見て、合っているものを残し、外れを消す。1 ファイル数分が数秒になる。

## 正直な限界

- ゼロショット分類はヒューリスティクス。「室内、暗い、クローズアップ」のような画の事実は得意だが、文脈や物語や好みが要るものは本当に苦手。出力を下書きとして扱い、本物のライブラリに入れる前に目で確認すること。
- タグの質は語彙としきい値で決まる。`tags.json` にないラベルは永遠に予測されないし、プロンプトが下手ならスコアも下手になる。
- CLIP ViT-B/32 は 2021 年の小さなモデル。どこでも動く代わり、細かい区別に奇跡は期待しないこと。
- CPU 速度はこの用途には十分（モデル読み込み後、短い動画なら 1 本数秒）。ただし数千本の長尺ライブラリはそれなりに時間がかかる。内容の変化が大きい長尺は `--frames` を増やすとよい。
